Selected coursework

Learning by investigating what is happening under the surface.

These assignments moved networking from diagrams and vocabulary into systems I could configure, observe, and explain.

01

Virtualization · System administration

Virtual Lab & Windows Management Tools

I configured an Ubuntu virtual machine in VirtualBox and connected course concepts to NAT, bridged, and host-only networking. Using NAT showed me how a VM can reach the Internet for updates without being directly exposed to other devices on the physical LAN.

I also built a custom Microsoft Management Console with Device Manager, Event Viewer, and Services. Exploring device properties, system events, and service configurations helped me understand how administrators diagnose and manage a Windows system.

  • VirtualBox
  • Ubuntu
  • MMC
  • Event Viewer
02

Wireshark · Application traffic

HTTP Request & Response Analysis

I captured and filtered HTTP traffic in Wireshark, then followed individual requests and responses to identify methods, host names, status codes, source and destination addresses, and full request URIs.

Seeing messages such as 200 OK, 304 Not Modified, and 401 Unauthorized inside real packets made the protocol easier to understand. The lab also demonstrated why sensitive information should not be sent through unencrypted HTTP.

  • HTTP
  • Packet filtering
  • Status codes
  • Traffic inspection
03

TCP · Reliability

TCP Fault Recovery Investigation

I used Wireshark Expert Information and display filters to compare duplicate acknowledgments, retransmissions, fast retransmissions, and TCP data packets in both a live download and a supplied lossy capture.

The most important takeaway was understanding what reliability actually costs. Packet loss adds delay and reduces throughput, but TCP uses sequence numbers, acknowledgments, reordering, and retransmission to give the application a complete byte stream.

  • TCP streams
  • Duplicate ACKs
  • Retransmissions
  • Rate calculations
04

Architecture · Network security

Addressing, Segmentation & Secure Design

Through assignments and quizzes, I practiced subnetting, CIDR notation, VLAN tagging, trunk links, DHCP relay, inter-VLAN routing, wireless security, authentication, and switch protections.

These topics helped me see that network security is not one product or setting. It comes from intentional design—separating traffic, limiting access, choosing secure protocols, monitoring activity, and understanding where each control operates.

  • IPv4 & CIDR
  • 802.1Q VLANs
  • RADIUS
  • Port security

Overall reflection

From memorizing protocols to reading the network.

At the beginning of the course, many networking concepts felt like separate definitions: layers, ports, addresses, frames, and protocols. The hands-on labs helped those pieces connect. Capturing traffic made it possible to see where an HTTP request travels, how TCP responds when data is lost, and why choices such as NAT, VLANs, encryption, and authentication matter.

The course also strengthened my confidence with troubleshooting. I learned to slow down, apply a focused filter, inspect the evidence, and explain what the packets or system tools were showing. That process connects directly to my interests in cybersecurity, cloud systems, and AI security because protecting technology starts with understanding how devices communicate and recognizing when that communication does not look normal.
